2.2Making decisions with if, elif, else

New file d02_if.py. It sorts a Mach number into a flight regime:

{{code:d02_if.py}} {{out:d02_if.py}}
if mach < 0.8:
"If this is True, run the indented lines below me." The line must end with a colon :.
regime = "subsonic"
This line is indented (pushed right by 4 spaces), which means it belongs to the if. It only runs when the question was True.
elif mach < 1.2:
"else if": checked only if every question above it was False. You can have as many elif lines as you need.
else:
Runs if none of the questions above were True. It's optional.
print(...) (not indented)
Back at the left edge, so it isn't part of the if. It always runs, after the decision is made.

Python checks from top to bottom and runs only the first branch that is True. Mach 6.2 fails < 0.8, < 1.2 and < 5, so it lands in else.

Indentation is part of the language

In Python, the spaces at the start of a line decide which lines belong together, a bit like sub-bullets in a list. The standard is 4 spaces. VS Code inserts 4 spaces when you press Tab and indents automatically after a colon. If the spacing is inconsistent, Python stops with an IndentationError.

2.3Lists: many values under one name

A list holds several values in order, inside square brackets and separated by commas. New file d02_lists.py:

{{code:d02_lists.py}} {{out:d02_lists.py}}

Each item has a position number called an index. Counting starts at 0, not 1. Negative numbers count from the end:

value: 0 10 20 30 40 index: 0 1 2 3 4 negative index: -5 -4 -3 -2 -1
altitudes_km[0]
The item at index 0, which is the first one.
altitudes_km[-1]
The last item. This works whatever the list's length.
altitudes_km[1:3]
A slice: items from index 1 up to but not including index 3, so indexes 1 and 2.
len(altitudes_km)
How many items the list holds.
altitudes_km.append(50)
Adds 50 to the end. .append is a function that belongs to lists (the dot again means "belonging to").
altitudes_km[0] = 5
Replaces the item at index 0.
sum(...), min(...), max(...)
Built-in functions for the total, the smallest and the largest value.

Common error: IndexError

A list with 5 items has indexes 0 to 4. Asking for altitudes_km[5] gives IndexError: list index out of range.

2.4Repeating work with a for loop

A loop runs the same lines several times. A for loop runs them once for each item in a list. New file d02_for.py:

{{code:d02_for.py}} {{out:d02_for.py}}
for h_km in altitudes_km:
"For each item in altitudes_km, put that item in the variable h_km and run the indented lines." The first time h_km is 0, the second time 10, and so on. You choose the name h_km; it can be anything.
The 3 indented lines
Run once per item. One pass through these lines is called an iteration.
rho = 1.225 * math.exp(-h / 8500)
A simple atmosphere model: density is 1.225 kg/m³ at sea level and falls by a factor e ≈ 2.72 every 8.5 km.
print("Done")
Not indented, so it runs once, after the loop has finished.

2.7while loops and your first simulation

A while loop keeps repeating as long as a condition is True. That's exactly what a simulation needs: "keep stepping time forward while the ball is still in the air."

The idea is called Euler's method, and it's the heart of every flight simulation. Over a small time step dt:

  • new height = old height + vertical speed × dt
  • new speed = old speed + acceleration × dt

The numbers that describe the ball at one instant (height and speed) are called its state. How fast they change (speed and acceleration) are its rates. Remember those two words: OpenMDAO and Dymos use them too. New file d02_while.py:

{{code:d02_while.py}} {{out:d02_while.py}}
First 5 lines
Gravity, plus the starting state (height 0, upward speed 30 m/s), the clock (t = 0) and the time step (0.01 s).
while h >= 0:
Check the condition. If the height is still 0 or more, run the indented block, then come back and check again. Stop when it becomes False.
h = h + v * dt
Move the ball by speed × time step.
v = v - g * dt
Gravity reduces the upward speed by g × time step.
t = t + dt
Advance the clock.

The simulation gives 6.13 s and the exact answer is 6.12 s. The small difference comes from the finite time step. Make dt 10 times smaller and the answer gets closer, but the loop runs 10 times more often.

Infinite loops

If the condition never becomes False (for example you forgot to update h), the loop runs forever. Click in the terminal and press Ctrl+C to stop it.
