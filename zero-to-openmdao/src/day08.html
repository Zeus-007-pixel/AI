8.1What OpenMDAO is, in plain words

OpenMDAO is NASA's framework for building engineering models from blocks and optimizing them. ("MDAO" means multidisciplinary design, analysis and optimization.) SciPy can optimize one function. OpenMDAO lets you build a big model from many small pieces, such as atmosphere, aerodynamics, propulsion and trajectory. It connects them, converts units, and works out the derivatives the optimizer needs efficiently. Dymos is built on top of it.

Five words cover the whole framework:

Problem the whole job: model + driver ├── driver what runs the model, e.g. an optimizer (Day 10) └── model the top Group, holding everything ├── Component one calculation block: inputs → outputs └── Group a container of components (and other groups) (Day 9) ├── Component └── Component
WordMeaning
ComponentOne calculation. You write it as a class with setup and compute, exactly like Day 5's MiniComponent.
GroupA box that holds components and wires them together.
modelThe top-level Group. Every Problem has one, called p.model.
DriverSomething that runs the model repeatedly, usually an optimizer.
ProblemThe object that owns all of the above. You create it, set it up, and run it.

8.2The first component, line by line

The same paraboloid as Day 7: f(x, y) = (x−3)² + xy + (y+4)² − 3. New file d08_paraboloid.py:

Part 1: the component class

import openmdao.api as om
Everything you need from OpenMDAO is in openmdao.api, nicknamed om.
class Paraboloid(om.ExplicitComponent):
Your component inherits from OpenMDAO's ExplicitComponent. "Explicit" means the outputs can be computed directly from the inputs with formulas. (Day 13 shows the other kind.)
def setup(self):
OpenMDAO calls this when the problem is set up. You declare your variables here.
self.add_input('x', val=0.0)
Declares an input called 'x' with starting value 0.0. add_input is a method inherited from ExplicitComponent, which is why it's called through self.
self.add_output('f', val=0.0)
Declares an output. Outputs are what compute must fill in.
self.declare_partials('*', '*', method='cs')
Tells OpenMDAO how to get derivatives, which optimizers need (Day 10). '*', '*' means "every output with respect to every input", and method='cs' means "work them out automatically with complex step". Day 11 explains this fully. For now, always include this line. Day 10 shows what goes wrong without it.
def compute(self, inputs, outputs):
OpenMDAO calls this every time the model runs. inputs and outputs work like dictionaries.
x = inputs['x']
Read an input by its name.
outputs['f'] = (x - 3.0)**2 + …
Calculate and store the output by name.

Part 2: the problem that runs it

p = om.Problem()
Create an empty Problem. It comes with an empty model, p.model.
p.model.add_subsystem('parab', Paraboloid(), promotes=['*'])
Put a component in the model. 'parab' is the name you give this copy. Paraboloid() creates the object (note the brackets). promotes=['*'] lets you refer to its variables by short names like 'x' instead of 'parab.x'. Section 8.5 shows the alternative.
p.setup()
OpenMDAO builds everything. This is when your setup method runs. Always call it after adding components and before setting values.
p.set_val('x', 3.0)
Give an input a value.
p.run_model()
Run the model once. OpenMDAO calls your compute.
p.get_val('f')
Read a result. It prints [-15.] with square brackets, because OpenMDAO always stores values as NumPy arrays, even single numbers (an array with one element). Use p.get_val('f')[0] to get the plain number.

Check by hand: f(3, −4) = 0 + (−12) + 0 − 3 = −15. Correct.

Things you'll notice

A new folder such as d08_paraboloid_out appears next to your file each time you run. OpenMDAO saves reports there. It's harmless and you can delete it any time.

Warning lines containing the word Warning may appear when OpenMDAO starts. A warning is not an error: the program still ran. Read warnings, because they sometimes point to real problems (Day 10 shows one), but they don't stop anything.

8.3Units: let OpenMDAO convert for you

Units bugs are the most common engineering bug (remember Day 4). OpenMDAO tracks units for you. New file d08_units.py:

{{code:d08_units.py}} {{out:d08_units.py}}
self.add_input('rho', val=1.225, units='kg/m**3')
Each variable can declare its units. Write powers with **.
p.set_val('v', 7200.0, units='km/h')
You give the value in km/h. OpenMDAO converts it to the component's units (m/s) before compute sees it. So your compute code can trust its units.
p.get_val('q', units='kPa')
Ask for the result in any compatible unit.

Common unit strings: m, km, ft, s, kg, N, kN, Pa, kPa, deg, rad, m/s, km/h, m/s**2, m**2, kg/m**3, W/m**2. Asking for incompatible units, such as a length in seconds, gives a clear error.

8.4Options: settings chosen when you build the model

Some numbers are not inputs that change during a run. They're fixed settings, like a reference area or the number of points to compute. Those are options. New file d08_options.py:

{{code:d08_options.py}} {{out:d08_options.py}}
def initialize(self):
A third method OpenMDAO calls, the first one, when the component object is created. Declare options here.
self.options.declare('S', default=10.0, desc='…')
Declares an option named 'S' with a default value and a description.
S = self.options['S']
Read an option inside compute (or setup).
Lift(S=20.0)
Set the option when you create the component, as a keyword argument.
p.model.list_outputs()
Prints a table of every output in the model: useful for checking everything at once.

Inputs are values the model, or an optimizer, can change between runs. Options are fixed when you build the model. The HGV code's num_nodes is an option.
