5.1What a class is

Think of a class as a blueprint, or a blank form. An object is one thing built from that blueprint, a filled-in copy. From one Vehicle blueprint you can build a glider object and an HGV object. Each holds its own data, but both know the same tricks.

  • Attributes are the data an object carries: its mass, its area.
  • Methods are functions that belong to the class and work on that data: its weight, its wing loading.

You've used objects already. A list is an object, and .append is one of its methods. Every OpenMDAO component you write will be a class.

5.2Your first class

New file d05_class.py:

{{code:d05_class.py}} {{out:d05_class.py}}
class Vehicle:
Starts a blueprint called Vehicle. By convention, class names use CapitalizedWords. Everything indented below belongs to the class.
def __init__(self, name, mass, S):
A special method (two underscores on each side, said "dunder init"). Python runs it automatically when you create a new object. It sets up the object's starting data.
self
The first parameter of every method. It means "the object this is being done to". When the glider runs __init__, self is the glider. You never pass self yourself; Python fills it in.
self.mass = mass
Stores the value of the parameter mass as an attribute of this object, so it's remembered after __init__ ends. Without self. it would vanish, because of scope (Day 3).
def weight(self, g=9.81):
A method. It reads the object's own data through self.mass.
glider = Vehicle("Glider-1", 500.0, 10.0)
Builds an object. Python creates an empty object and calls __init__(new_object, "Glider-1", 500.0, 10.0), then stores the object in glider.
glider.weight()
Calls the method. Python passes glider as self automatically, which is why the brackets can be empty.
hgv.mass = 1100.0
Changes one object's attribute. The glider is unaffected, because each object has its own data.

Common error: forgetting self

If you write def wing_loading(): without self, then glider.wing_loading() fails with TypeError: Vehicle.wing_loading() takes 0 positional arguments but 1 was given. The "1 given" is the object Python passed in as self. Inside a method, writing mass instead of self.mass gives a NameError.

5.3Inheritance: building on an existing class

A glider is a vehicle with extra aerodynamic data. Instead of copying Vehicle, we inherit from it. New file d05_inherit.py:

{{code:d05_inherit.py}} {{out:d05_inherit.py}}
class Glider(Vehicle):
The class in brackets is the parent. Glider automatically gets every method of Vehicle, such as weight, without retyping it.
super().__init__(name, mass, S)
super() means "my parent class". This line runs Vehicle's own __init__, which stores name, mass and S. Then the next lines store the glider's extra data.
def max_LD(self):
A new method that only gliders have.
def describe(self): in Glider
Overriding: the child defines a method with the same name as the parent's. For gliders, the child's version wins.

5.4How frameworks call your code: OpenMDAO in miniature

This section explains how OpenMDAO works, before you've touched OpenMDAO.

A framework is a library that runs your code at the right moments. It gives you a parent class with empty methods. You write a child class that fills them in, and the framework calls them. Here is a 25-line imitation of OpenMDAO's ExplicitComponent. New file d05_framework.py:

{{code:d05_framework.py}} {{out:d05_framework.py}}
class MiniComponent:
The framework's parent class, the part "the library authors" wrote.
self.inputs = {} and self.outputs = {}
Each component holds two dictionaries for its values.
self.setup() inside __init__
When a component is created, the framework calls setup. Because of overriding, it runs your version of setup.
def setup(self): pass
pass means "do nothing". It's a placeholder for an empty block. The parent leaves these methods empty for you to fill in.
def run(self): self.compute(self.inputs, self.outputs)
When the framework runs the component, it calls your compute and hands it the two dictionaries.
class DynamicPressure(MiniComponent):
Your code: inherit from the framework class, and fill in only setup (declare inputs and outputs) and compute (the physics).
outputs["q"] = 0.5 * inputs["rho"] * inputs["v"] ** 2
Read inputs by name and store the output by name, just like dictionaries.
Our mini versionReal OpenMDAO (Day 8)

The big idea

In OpenMDAO you never call setup or compute yourself. You write them, and OpenMDAO decides when to run them. When the HGV code from earlier in our conversation said def compute(self, inputs, outputs):, this is all that was happening.
