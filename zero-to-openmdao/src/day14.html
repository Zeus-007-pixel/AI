Warm-up from memory

  1. What is a residual?
  2. In solve_ivp, what do .terminal = True and .direction = -1 do on an event function?
  3. Which derivative method must you use for a component that runs a simulation, and why?
Answers

1. A quantity that must become zero when an implicit output is correct. 2. Stop the simulation when the event happens, and only count crossings going downward. 3. method='fd', because complex numbers can't pass through the solver, so only finite differences work.

14.1The project

Our glider (500 kg, 10 m², CD = 0.02 + 0.1·CL²) is released at 5 km altitude, flying level at 100 m/s. It holds one constant angle of attack until it lands. Which angle gives the longest range?

The plan:

  1. An ODE function with the flat-Earth glider equations (Day 7 style).
  2. A component whose compute runs a full solve_ivp simulation: α in, range out.
  3. An optimizer that changes α to maximize range, with FD derivatives (Day 11).

Before reading the solution, try to write it yourself using the plan above and your Day 7 and Day 10 files. Give yourself an hour, then compare with the code below.

Part 1: the physics

def glider_rates(t, state, alpha, m, S):
A Day 7 ODE function with three extra parameters after the usual t, state. The state is [x, h, v, gamma]: distance, altitude, speed and flight-path angle.
The return [...] list
The four rates, the same equations as GliderODE (Day 12): ẋ = v cos γ, ḣ = v sin γ, v̇ = −D/m − g sin γ, γ̇ = (L/m − g cos γ)/v.
def reach_ground(t, state, alpha, m, S):
An event function. It must accept the same extra parameters as the ODE, even though it doesn't use them.

Part 2: the simulation component

self.options.declare('m', default=500.0, …)
Mass and area are fixed options. α, the launch height and the launch speed are inputs, so an optimizer can change them.
self.declare_partials('*', '*', method='fd', step=1e-6, step_calc='rel')
Finite differences, because complex step can't pass through solve_ivp. step_calc='rel' makes the step relative to the input's size (1e-6 × the value), which suits inputs of very different sizes.
alpha = inputs['alpha'][0]
Inputs are arrays. [0] takes the single number out, because solve_ivp wants plain numbers here.
start = [0.0, inputs['h0'][0], inputs['v0'][0], 0.0]
Starting state: x = 0, the given height and speed, and level flight (γ = 0).
solve_ivp(glider_rates, (0.0, 1e5), start, args=(alpha, m, S), events=reach_ground, rtol=1e-10, atol=1e-8)
args=(...) passes the extra values to both the ODE and the event function, after t and state. The time span is "up to 100 000 s", but the event stops it at landing. The tight tolerances make the range smooth, so FD derivatives are accurate. That's essential, because noisy derivatives confuse optimizers.
outputs['range'] = sol.y[0, -1]
Final x, the landing point. sol.t[-1] is the landing time.

Part 3: the optimization

add_design_var('alpha', lower=1.0, upper=15.0, units='deg')
Search between 1° and 15°.
add_objective('range', ref=-1e4)
A negative ref means maximize, and 1e4 is the typical size (10 km) for scaling.

Result: α = 6.23°, range 58.9 km, flight time about 20 minutes. Sanity check: the best L/D was 11.18 at 6.4° (Days 6 and 10). Gliding 5 km down at L/D ≈ 11 gives about 56 km, and the starting speed adds a little extra energy. The optimizer found almost exactly the best-L/D angle, which is what glider pilots are taught.

14.3The wall you just hit

We forced one constant angle for the whole flight. A real pilot changes it continuously. So what's the best α at every moment? You could make α a list of, say, 100 values (one per 10 seconds) as 100 design variables. But then:

  • each FD derivative needs 100 extra simulations per optimizer iteration, which is very slow
  • adaptive solver steps and the landing event make the range slightly jumpy, so the FD derivatives get noisy and the optimizer struggles
  • adding constraints on the path, such as "q must stay below some limit at every moment", gets awkward

Finding a whole history of controls is called optimal control, and it needs a different approach. That approach is Dymos, tomorrow.
