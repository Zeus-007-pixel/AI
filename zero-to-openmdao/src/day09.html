9.1A model made of several blocks

Real models are chains of calculations. To get lift and drag from altitude and speed:

h ──► [ Atmosphere ] ──rho──► [ DynamicPressure ] ──q──► [ Aero ] ──► L, D ▲ ▲ v alpha

Each box is a component. An output of one box becomes an input of the next, and that link is a connection. A Group holds the boxes and their connections.

class FlightCondition(om.Group):
Your own Group class, which inherits from om.Group.
def setup(self): inside the group
For a Group, setup adds the subsystems (the parts) instead of variables.
self.add_subsystem('atmos', Atmosphere(), promotes=['*'])
Adds a component to this group. promotes=['*'] lifts all its variables up to the group level, using their short names.
The key rule of promotion
When an output and an input are promoted to the same name, OpenMDAO connects them automatically. atmos outputs rho and dynp has an input rho, so they're connected. Likewise q links dynp to aero.
p.model.add_subsystem('flight', FlightCondition(), promotes=['*'])
A Group goes into the model exactly like a component. Groups can hold groups, as deep as you like.
p.set_val('h', 5000.0)
h, v and alpha are inputs that no output feeds. OpenMDAO quietly creates a hidden source for each unconnected input (called "auto IVC"), so you can set them with set_val.

Sanity check: at 5 km, ρ = 0.6803 kg/m³, so q = ½ · 0.6803 · 100² = 3401 Pa. ✓

Instead of promoting, you can wire outputs to inputs explicitly using full paths. New file d09_connect.py:

model.connect('atmos.rho', 'dynp.rho') means "feed output rho of atmos into input rho of dynp". The order is always output first, then input. Use connect when names don't match, or when you want every link to be visible in the code.

9.4Order matters

By default OpenMDAO runs the subsystems of a group once, in the order you added them. Here is d09_group.py with the first two components swapped, saved as d09_wrong_order.py:

self.add_subsystem('dynp', DynamicPressure(), promotes=['*']) # WRONG ORDER self.add_subsystem('atmos', Atmosphere(), promotes=['*']) {{out:d09_wrong_order.py}}

No error, but q is wrong: 6125 Pa instead of 3401. dynp ran before atmos had computed the density, so it used rho's starting value of 1.225. Add components in the order the data flows. (Groups also have an auto_order option that sorts them for you, but the simple habit is safer.)

9.5Quick equations with ExecComp

Writing a whole class for LD = L / D is overkill. om.ExecComp makes a component from a formula written as text. New file d09_execcomp.py:

{{code:d09_execcomp.py}} {{out:d09_execcomp.py}}
om.ExecComp('LD = L / D')
Creates a component with inputs L and D and output LD. It works out its own derivatives, so no declare_partials is needed.
dL={'units': 'N'}, …, g={'units': 'm/s**2', 'val': 9.81}
Units and starting values for each variable, given as a small dictionary per variable. Without units, ExecComp variables have none, and OpenMDAO warns if you connect one to a variable that has units.
p.model.set_input_defaults('L', 5000.0, units='N')
L is an input to both ExecComps, promoted to the same name, but one declares units and the other doesn't. set_input_defaults tells OpenMDAO which value and units the shared input should have. Day 10 shows the error you get without it.

9.6Seeing your model: the N2 diagram

OpenMDAO can draw your model as an interactive web page. New file d09_n2.py:

{{code:d09_n2.py}}

Open my_model_n2.html in your web browser, or use show_browser=True to open it automatically. (Every run also saves one as n2.html in the …_out/reports folder.) How to read it:

  • The coloured boxes on the diagonal are your variables, grouped by component.
  • A dark square off the diagonal is a connection. Above the diagonal, data flows downward to a later component. Below the diagonal, data flows back up to an earlier one: a feedback loop, which needs a solver (Day 13).
  • Click a group on the left to zoom in. Hover a square to see exactly which output feeds which input.

Make it a habit: when a model gives strange numbers, look at its N2 diagram first. Unconnected inputs and wrong connections are easy to spot there.
