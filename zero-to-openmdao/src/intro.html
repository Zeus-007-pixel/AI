Zero to OpenMDAO

Five rules that make this work

  1. Type the code yourself. Don't copy and paste it. Typing makes you notice every bracket, colon and space, and those details are exactly where beginners get stuck. The Copy buttons are only for when you're stuck.
  2. Run every example and check your output matches the course. If it doesn't, find the difference before moving on.
  3. Change one thing and predict. After an example works, change one number and say out loud what you think will happen. Then run it. This is the fastest way to learn.
  4. Read errors from the bottom up. The last line of an error message says what went wrong. The lines above it say where. Day 1 shows you how.
  5. Try each exercise for at least 15 minutes before opening the solution. Being stuck for a while is part of learning, not a sign you're failing.

When you're stuck

Come back to the chat where this course was made. Paste your code and the whole error message, and say which day and exercise you're on. You can also ask for a quiz, for example "quiz me on Day 6".

Three weeks or two?

Three weeks: do one course day per real day. Use the 5–6 spare days to redo any exercise where you opened the solution early, and to go back over Days 5, 8 and 11, which are the hardest.

Two weeks (14 days): skip Day 13 for now. You won't need it for your first Dymos problems. Do everything else in order.

Keep all your files in one folder called pycourse. Files are named by day (d01_hello.py, d02_if.py, …). Later days import files you made on earlier days, so they need to sit side by side.
